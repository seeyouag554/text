# 咖啡因摄入记录 App 设计方案

## 1. 产品定位与目标
- **核心目标**：帮助用户随时记录咖啡因摄入，实时对照健康阈值，形成长期摄入习惯分析。
- **目标用户**：注重健康、需要通过咖啡因调节精神状态的上班族、学生，以及需要控制睡眠质量的人群。
- **产品亮点**：基于体重的个性化阈值、睡前六小时智能提醒、提神有效量提示、长期趋势分析。

## 2. 功能模块概览
| 模块 | 描述 |
| --- | --- |
| 账号与体征管理 | 登录注册、体重管理、睡眠时间与提醒设置 |
| 咖啡因记录 | 快速新增/编辑/删除摄入记录，支持常用饮品模板 |
| 阈值监控 | 按日累计、单次摄入、睡前 6 小时规则实时校验 |
| 数据可视化 | 日/周/月统计图表，超标次数与分布分析 |
| 提醒与推送 | 睡前提醒、接近阈值提醒、提神有效量提示 |
| 数据同步 | 本地存储 + 云端备份/多端同步 |

## 3. 技术选型建议
- **移动端技术栈**：推荐使用 React Native（跨平台）或 Flutter。
- **后端**：Node.js (NestJS) 或 Python (FastAPI)，提供 RESTful API。
- **数据库**：PostgreSQL（结构化数据 + JSON 扩展），并使用 Redis 做缓存与任务调度。
- **推送服务**：Firebase Cloud Messaging (FCM) 或 APNs + 极光推送。
- **数据可视化**：移动端使用 Victory Native / ECharts；后台管理可搭配 Superset 或自建 Dashboard。

## 4. 数据模型设计
### 4.1 关键实体
- **User**：包含账号信息、体重记录（kg）、默认睡眠时间、提醒偏好。
- **CaffeineItem**：常用饮品模板，字段包括名称、默认咖啡因含量、体积、品牌等。
- **IntakeRecord**：摄入记录，包含用户、时间、饮品、实际摄入咖啡因（mg）、体重快照、备注、位置。
- **DailySummary**：每日聚合数据，记录总摄入、阈值对比、超标标记。
- **NotificationLog**：推送记录与状态。

### 4.2 字段示例
```sql
CREATE TABLE intake_record (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL REFERENCES app_user(id),
    caffeine_item_id UUID REFERENCES caffeine_item(id),
    consumed_at TIMESTAMP WITH TIME ZONE NOT NULL,
    caffeine_mg NUMERIC(6,1) NOT NULL,
    weight_snapshot_kg NUMERIC(5,2),
    notes TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

## 5. 阈值与规则实现
1. **每日总摄入限制**
   - 计算逻辑：统计当天 0:00-24:00 累计咖啡因 `total_mg`，与 400mg 与 `weight_kg * 5.7` 中较小值比较。
   - 提醒策略：累计达到 80% 时标记“即将超标”，≥100% 时标记“已超标”。
2. **单次摄入限制**
   - 记录表单提交时校验单次摄入是否 ≤200mg 或 `weight_kg * 3`。
   - 超标则弹窗提示，并允许用户标记“仍然保存”或“调整剂量”。
3. **睡前 6 小时限制**
   - 用户配置睡眠时间 `sleep_time`；摄入时间 `t` 必须满足 `t <= sleep_time - 6h`。
   - 若不满足，给予强提醒并阻止保存，除非用户开启“强制记录”选项。
4. **提神有效量提示**
   - 当单次摄入量在 20–200mg（或 0.7–3mg/kg）之间时，记录卡片显示“提神有效”。

## 6. 移动端界面流程
1. **启动页/登录**：支持手机号 + 验证码登录，首次登录填写体重和睡眠时间。
2. **首页仪表盘**：
   - 顶部显示今日累计摄入 vs 阈值，环形图或进度条。
   - 中部快速添加按钮，列出常用饮品快捷入口。
   - 底部展示今日时间轴，每条记录标明提神有效/超标状态。
3. **添加记录流程**：
   - 选择饮品模板或自定义，输入份量，自动计算咖啡因。
   - 显示阈值校验结果，允许添加备注、体感、位置。
4. **统计页**：
   - 切换日/周/月，展示趋势图、超标次数、晚间摄入频次。
   - 支持导出 CSV 或分享报告。
5. **设置页**：
   - 体重管理（可记录历史曲线）、睡眠时间、提醒策略、模板库管理。

## 7. 后端 API 设计示例
| 方法 | 路径 | 描述 |
| --- | --- | --- |
| POST | /auth/login | 登录/注册 |
| GET | /users/me | 获取当前用户信息 |
| PUT | /users/me | 更新体重、睡眠时间等 |
| GET | /caffeine-items | 获取常用饮品列表 |
| POST | /intake-records | 新增摄入记录（含阈值校验结果） |
| GET | /intake-records?date= | 查询某天记录 |
| GET | /summaries/daily?start=&end= | 获取区间聚合数据 |
| POST | /notifications/test | 测试推送 |

API 返回值包含阈值校验字段，如 `daily_limit_status`, `single_intake_status`, `sleep_window_status`。

## 8. 提醒与自动化
- **本地提醒**：移动端使用系统通知 API，在睡前 6 小时时触发“停止摄入”提醒。
- **服务器推送**：每日早晨推送前一天摘要；当全天达到 70%、90%、100% 阈值时推送不同级别提醒。
- **智能推荐**：根据历史摄入与睡眠质量（若记录）提供“低咖啡因日”建议。

## 9. 安全与隐私
- 使用 HTTPS，全程数据加密传输。
- 用户敏感信息（手机号、邮件）以加盐哈希存储。
- 提供数据导出与删除账户功能，满足隐私法合规（GDPR/中国个人信息保护法）。
- 关键操作（删除记录、修改阈值策略）需二次确认。

## 10. 开发迭代建议
1. **MVP 阶段**：完成账户体系、摄入记录、阈值计算、基础提醒。
2. **增强阶段**：加入统计分析、数据可视化、饮品模板库。
3. **进阶阶段**：引入睡眠质量、个性化推荐、AI 分析。
4. **商业化探索**：付费功能（健康报告、个性化建议）、品牌合作、设备联动。

## 11. 测试与度量
- 单元测试覆盖阈值计算、时间窗校验、API 权限控制。
- 集成测试覆盖记录创建/修改/删除流程。
- 监控指标：每日活跃、记录数、超标提醒命中率、留存率。
- 埋点：记录每次提醒触达、用户处理操作、提神有效提示的点击率。

## 12. 后续扩展想法
- 支持扫描条形码识别饮品。
- 与可穿戴设备同步心率、睡眠时长，关联分析。
- 社区功能：分享低咖啡因饮品、健康习惯。
- 个性化 AI 助手：根据历史数据建议摄入时间与剂量。
